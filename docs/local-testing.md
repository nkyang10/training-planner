# Local testing stage (SQLite, seeded runner, real usage)

This is the stage for using the product as a runner would use it, not for looking at empty pages. It runs the two real
processes against a real SQLite database, seeded with one fictional runner who has a history, an open review, a pain
report and a wizard they have changed their mind about.

## What is running

| Process | Command | URL |
|---|---|---|
| web UI | `PORT=8081 npx tsx apps/web/src/index.ts` | http://127.0.0.1:8081 (or the machine's LAN address, same port) |
| API | `PORT=8082 npx tsx apps/api/src/index.ts` | http://127.0.0.1:8082 |

Both need the same environment:

```powershell
$env:API_TOKENS = '{"demo-token":"d3d3d3d3-d3d3-4d3d-8d3d-d3d3d3d3d3d3"}'
$env:TRAINING_PLANNER_DB = 'sqlite:data/local.sqlite'
```

The API additionally reads the model port (the owner's endpoint); without it the process logs `no model port` and
`POST /reviews/advisor` answers `503`:

```powershell
$env:TRAINING_PLANNER_MODEL_BASE_URL = 'http://192.168.1.202:8102/v1'
$env:TRAINING_PLANNER_MODEL_API_KEY  = '<supplied at run time, never committed>'
$env:TRAINING_PLANNER_MODEL_NAME     = 'dgx/general'
```

Port 8080 is used by another local service on this machine, so the API runs on 8082; every port is `PORT`, not a
constant.

## Seed (or reset) the runner

Stop both processes first (the SQLite adapter holds the file open), then:

```powershell
npx tsx tools/seed-local.ts
```

It writes `data/local.sqlite` (git-ignored) and prints the token and the review id. Sign in at `/login` with
`demo-token`.

## What the seeded runner has

| Piece | Detail |
|---|---|
| orientation | goal `finish` (originally `time`), runs Mon/Wed/Fri/Sun (originally three days), conservative risk |
| plan | four weeks from 2026-10-19, generated by the real planner |
| log | 17 entries: mostly completed, two missed (`2026-10-24`, `2026-11-01`), one partial (`2026-10-30`) |
| pain | one right-knee report (3/10) on 2026-11-03, written as a pain row so the pain page has a trajectory |
| comment | one stored system comment for 2026-11-03, exactly as the runner read it |
| review | one open review with two real options: keep the plan, or shorten the 2026-11-11 easy day by 2 km |
| guidelines | two public (progression ceiling, tone) and one internal safety rule that must never appear on a runner page |
| consent | granted for `review-decision` |
| audit | one accepted AI decision row, so the audit trail is visible in `/export` |

## What to look at (and what was fixed for this stage)

The first pass through these pages found real UI/UX gaps; they are fixed in this stage and pinned by tests:

| Page | Before | Now |
|---|---|---|
| review sheet | showed wire labelKeys (`keep-the-plan`, `ease-the-easy-day`) | shows sentences ("Keep the plan", "Make the easy day shorter"); replan keeps its honest size line |
| console | availability row was blank (and crashed once answers used `values`) | shows "Monday, Wednesday, Friday, Sunday" and the original choice next to it |
| wizard (finished) | "The wizard is done." with no way back | lists every answer with a `Change` link (`/wizard?step=...`) |
| day page | always checked "Done as planned"; asked "logging an older day?" on every visit | checks the logged outcome; asks for a correction reason only when correcting an existing entry |
| pain page | listed a vocabulary sentence instead of the report's flags | lists the report's own flags (night pain, gait change, known injury) |
| season | past weeks were labelled `done`, next to "planned …" | labelled `past`, so "past planned 15.8 km · done 15.8 km" reads as one fact |

Also verified as real usage: the calendar banner is a link to the review; accepting the review shows
"Accepted. The change starts on …", activates the staged plan version (the export then has two plan versions), and the
banner disappears.

## Mobile navigation, lookback and the shape of the block (2026-11-05 pass)

The first phone-sized pass found the shell had **no navigation**: the only links were in a footer below the fold. Fixed
and verified:

| Gap | Now |
|---|---|
| no navigation on a phone | a `tabs` bar in the shell (Week · Month · Season · Console · Orientation · Pain · Export); on screens ≤ 640 px it is a **fixed bottom bar** with 44 px touch targets and safe-area padding |
| no lookback | the calendar accepts `?week=YYYY-MM-DD` and has **Previous week / Next week** links; every week has its own page at `/week/:weekStart` with the same rows as the calendar |
| no monthly view | `/month/:YYYY-MM` lists the weeks that touch the month with planned/done km, sessions and links into each week; previous/next month links |
| no reference to the shape of the block | the season and month views mark the **peak week** (the week with the most planned kilometres) and the **final surge** (the plan's last planned week); the calendar shows both as one line. These are plan facts, not physiological claims |
| a note had nowhere to show | the calendar and week views render the runner's own day note (`Note: …`), not only the system comment |

Still not built: a **weekly note** that is its own record (day notes are supported and shown). That needs a storage
record + contract, which is the next slice; it is not silently implied here.

## Connections: Strava / Garmin (2026-11-05 pass)

The web shell now has a **Connections** tab (`/connections`). It does three things and refuses to pretend about the rest:

| Action | What happens |
|---|---|
| Link Garmin | Paste a **Garmin Personal API key** (Garmin Connect → Settings → Personal API Key). The web process proxies the exchange to the API; the connection stores the account name, never the key or token |
| Choose sync source | Radio group: manual only / Strava / Garmin / both; saved per runner |
| Sync now (Garmin) | Imports completed runs with distance > 0 in the chosen date range as day entries through the normal entry pipeline; repeated sync is a duplicate, never a second entry |
| Link Strava | Shows the honest sentence: a registered app (client ID, secret, public callback) is required; `/connections/strava/start` answers `503 strava-not-configured` until then |

Environment for a local Garmin link (the key is a secret; never commit it):

```
$env:GARMIN_PERSONAL_API_KEY = '<Garmin personal API key>'
```

The API must be running on :8082 and the web on :8081; the web proxies Garmin actions to `TRAINING_PLANNER_API_URL`
(default `http://127.0.0.1:8082`). Verified live on 2026-11-05: token exchange, profile display name, activity list,
and a sync that appended a day entry with idempotency key `garmin:<activityId>`.

Still not built: token storage in a secret manager (the record keeps `credentialRef` only), Strava callback state, and a
scheduled sync. Those are deployment decisions, not UI gaps.

## Calendar grid: week and month (2026-11-05 pass)

The first phone/laptop pass showed the "calendar" was a **list of rows**, which answers "what is next" but not "what does
this period look like". Changed and verified:

| Before | Now |
|---|---|
| week = a vertical list of 7 rows | **7 day cards in a grid** (`.week-grid`), each with date, session, logged state, note/comment; today has an accent ring |
| month = a list of weeks | **real month grid** (`.month-grid`, Monday first, padded to whole weeks): weekday headers, day numbers, session text, status dots (done/missed/rest) |
| no totals | a totals line above the week: planned km · done km · sessions done/planned |
| no date jump | a **Go to date** picker on the week view (`/jump?date=…` → the week containing that date) |
| period navigation only prev/next | period nav now carries **Today · Month · Season** on the week, and **This month · Week · Season** on the month |
| 8 flat tabs | unchanged in this pass; grouping the secondary tabs is the next navigation slice |

On ≤640 px the week grid becomes two columns; the month grid stays seven columns with the session text hidden so the
shape survives.

## Tablet app shell and visual revamp (2026-11-05 pass)

The product no longer looks like a mini tool. The shell is a tablet app: a fixed ember-lit rail, a blurred topbar, a
1320px working column, and page headers with a hero band and stat tiles.

| Piece | What changed |
|---|---|
| Shell | `.app-shell` = sidebar (Train / Log / Plan / Account groups) + topbar + `.main`; the same destinations fold into the bottom `.tabs` on ≤900 px |
| Type | Bricolage Grotesque display + Inter body (Google Fonts with system fallbacks); page titles clamp 30–46 px |
| Colour | ember `#FF5A1F`, solar `#FFB020`, coral `#FF4D6D`, lime `#C6F24E` on cream `#FFF8F0`; `--heat` gradient for primary actions, active nav and heroes |
| Pages | `page-head` (eyebrow/title/sub) on week, month, season, day, connections, console, wizard; week and month add generated hero art; season adds three stat tiles |
| Art | ComfyUI Flux 2 generated `hero-week.png`, `hero-season.png`, `surface-texture.png`; served from `/static/assets/*.png` with a path-traversal guard |
| Sign-in | `main-auth` layout: brand + card, no rail |

Honest gaps: `renderWeek`, `renderPain` and `renderReview` still use their old plain headings (flagged as follow-up); the
rail has no active-item highlight yet; the month grid hides session text under 900 px and relies on the status dot.

| Piece | Behaviour |
|---|---|
| `/stats` | training completeness: done/planned sessions, done/planned km, adherence %, logged days; a weekly table; the coach's comments collected from the last 28 days |

## Honest limits

| Limit | Why |
|---|---|
| one runner, one token | it is a local demo, not a multi-tenant deployment |
| SQLite | a development adapter: no RLS, no roles, no purge path; Postgres remains the tenancy boundary |
| fictional data | nothing here is a real athlete's log; the seed is generated |
| the model | the endpoint is real and was checked live, but the advisor route's budget is per runner per day; a seeded open review also uses the weekly prompt budget |
| M2 criteria | still need real runners; this stage is for using the product, not for measuring it |

## Resetting after trying a decision

Accepting or declining the review mutates the seeded database. To get the initial state back: stop both processes,
`npx tsx tools/seed-local.ts`, start them again.
